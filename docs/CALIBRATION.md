# 校正プロファイル v1

校正管理の第一段階として、既存CameraCalibrationを検証情報付きプロファイルへ包む。従来JSONはプレビューで使用できるが、LIVE／RECORD開始には検証済みプロファイルが必要。

## ファイル契約

JSONのトップレベルは以下。日時はISO 8601。`camera`の内部はExamples/Phase1/CameraCalibration.jsonと同じ形式。

入力を選択し、Inspectorの校正読込ボタン横のコピーアイコンから現在のカメラIDを取得できる。

| フィールド | 内容 |
| --- | --- |
| schemaVersion | 1。未知版は拒否 |
| id / revision | プロファイルUUIDと1以上の版番号 |
| camera | 内部・外部パラメータ、歪み、breathing、値の出所 |
| cameraID | 現在選択しているDevice RegistryのUUID |
| lensID | レンズ構成の識別子。現段階では記録用 |
| validatedAt / expiresAt | 最終検証日時と、その後の有効期限 |
| reprojectionRMSEPixels | 有限・非負の再投影RMSE |
| sampleCount | 検証に使用した点数。4以上 |
| stageConvention | RH-m-Yup-minusZ |
| stageRegistration | 任意。Node ID・接続ID・参照空間revision・固定日時・T_stage_from_nodeWorld。旧ファイルでは省略可能 |
| checkerboardMeasurement | 任意。ボード対応点から求めた外部姿勢の測定条件・点列・最大残差・フォーカス・反復回数 |

ファイルは1MiB以下。寸法は整数、外部パラメータはスケール・せん断・反転のない剛体変換に限る。プロファイル形式の不正ファイルを旧形式として読み直すフォールバックは行わない。保存は形式検証後にatomic writeを行う。

## 本番前チェック

推定値、期限切れ、未来の検証日時、RMSEが2pxを超える値、選択カメラID／実入力寸法の不一致、追跡基準の失効では開始を拒否する。メーカー値でも検証情報を必要とする。LIVE／RECORD中も期限・入力・追跡基準を評価し、失効時は既存の描画保護へ接続する。校正・シーン・入力の変更操作は本番中に抑止する。

再接続、再ローカライズ、追跡基準の再設定で校正が失効した場合、アプリの現在のセッション中は同じID・同じrevisionの再読込では復帰できない。物理的な再検証を行い、新しいrevisionを用意する。失効履歴の永続化、端末IDの長期安定化、測定ツールからの自動発行は今後の作業。

旧形式を読み込んだ場合は検証済みという情報を補わない。Inspectorで不足理由を確認できる。現在の診断JSON v13は校正プロファイルにステージ対応とボード測定条件も含めて保存する。

公称焦点距離の設定が基準値と異なる場合、フォーカス設定がbreathing表の範囲外の場合も本番開始・ステージ固定を拒否する。外部姿勢の測定から新revisionを生成する手順は[ボード対応点による校正](CHECKERBOARD-CALIBRATION.md)を参照。

## Nodeワールドとステージの対応

追跡Nodeの本番入力にはステージ対応が必要。プロファイルを読み込み、カメラを`camera.worldFromCamera`に記録された実測ステージ姿勢へ物理的に合わせて静止し、Inspectorの「ステージを固定」を押す。これは操作者による既知姿勢の確認であり、画像から姿勢を自動検出する操作ではない。

`T_stage_from_nodeWorld = T_stage_from_camera × inverse(T_nodeWorld_from_camera)`を計算する。その後の描画は`T_stage_from_nodeWorld × T_nodeWorld_from_camera(t)`を使い、最初のPoseとの差分によるプレビュー移動と区別する。

固定には対象カメラ・映像寸法・検証期限の一致、推定以外の校正、正常な追跡と有効な同期が必要。映像・PoseはHost時計で双方150ms以内、時刻差50ms以内を要求する。直近にPoseを拒否している場合は固定できない。未知の取得時刻や古い測定で固定しない。

固定するとプロファイルrevisionを増やし、Node ID・接続ID・参照空間revision・固定日時・剛体変換を保存する。既存の内部校正の検証日時・残差は書き換えない。保存アイコンからJSONを書き出せる。保存自体は校正品質を再認定する操作ではない。

再接続・再ローカライズ・追跡基準変更後は古い対応を使わない。再ローカライズ後は「追跡基準を再設定」で基準変更を確認し、正常な測定が戻ってから既知の物理姿勢へ合わせ直して再固定・保存する。接続IDに結び付くため、アプリ再起動後に古いファイルを読んでも本番で無条件に再利用されない。対応がない旧プロファイルは静止カメラの検証に引き続き使えるが、追跡Nodeの本番開始には手動固定が必要。

## 適用範囲と残作業

AprilTag／チェッカーボードの画像検出、実機レンズID・AF位置の自動取得は未実装。順序付き対応点と既知のボード姿勢からカメラの外部姿勢を計算できるが、ボード姿勢や内部校正は測定工程で正しく用意する必要がある。署名や測定証明の真正性までは保証しない。

`cameraID`は現在のアプリの入力IDであり、端末再登録後に変わる場合は再照合が必要。Node別の対応は各カメラのプロファイルに保存する。複数Nodeのプロファイル自動切替・管理UIはPhase 4以降。手動固定の物理的な精度認定はPending。

全125件のテストで、期限境界、出所、残差、対象・寸法不一致、参照変更、剛体検証、ファイル往復、旧形式読込、未知版拒否、未検証での本番開始拒否に加え、ステージ変換の位置・回転、接続・revisionの拒否、時刻条件、ボード対応点からの姿勢算出とフォーカス適用範囲を確認した。実カメラの精度と、本番中の失効時の実機表示はROADMAPのPendingに残す。
