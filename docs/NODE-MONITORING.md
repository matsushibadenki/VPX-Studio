# Node監視

MacのヘッダーにあるネットワークアイコンからNodeモニターを開く。入力の選択に関係なく、接続履歴のあるiPhoneをNode IDごとに表示する。表示名が同じでも内部では別のNodeとして扱う。

## 計測値

- 映像取得後経過は、同期済みの取得時刻から現在までの時間。選択外Nodeもデコード後に計測する。500ms超を警告し、古いフレームのデコード時間は表示しない。
- デコード時間はVideoToolbox投入から完了まで。RTT・ジッターは時計同期の計測値で、映像伝送専用のジッター測定ではない。
- Poseの品質・取得後経過、時計の鮮度、最後のAR状態を表示する。AR状態の理由は最後のイベントであり、現在のPose品質と合わせて判断する。
- バッテリーは0〜100%。取得できなければ`—`。充電状態も診断JSONに保存する。
- 温度負荷はiOSの`ProcessInfo.thermalState`による正常・軽度・高負荷・危険の分類。端末温度の摂氏測定値ではない。
- 取得・エンコード状態はiPhoneの取得・エンコーダ稼働フラグ。送信の一時停止とは別に表示する。Macまでの正常な映像到着は映像取得後経過で確認する。

## 伝送と鮮度

HostとiPhoneはCaptureプロトコル版4に揃える。異なる版のHelloは拒否する。既存のペアリング情報は変更しない。

iPhoneは接続中のみバッテリー監視を有効化し、状態を毎秒、既存のAES-GCM保護UDPチャネルへ送る。停止・切断時にタスクを取り消し、以前のバッテリー監視設定を復元する。映像停止後も接続が続く間は端末状態を送信する。

Hostは認証済み接続ID、UDPリプレイ防止、Node単位のシーケンスと取得時刻の増加を確認する。同期済みHost時刻へ変換し、3秒より古い／50msより未来の状態、不正なバッテリー値、時計同期がない状態を受理しない。受信時刻だけで古い情報を新しく見せない。受理後も3秒または時計の失効で状態を非表示にし、切断・再接続ではそのNodeの状態を破棄する。

## 保存と検証

再接続時は同じNode IDでも新しい映像ソース・デコーダ・ジッターバッファを割り当てる。表示用mailboxは接続IDを照合し、旧接続から遅れて完了した映像を拒否する。置換前にmailboxを無効化し、旧デコーダの終了処理中のコールバックも新しい映像へ混入させない。

切断時は対象NodeをRealtimeCoreからdetachし、HEVCデコーダを解放する。選択Nodeならmailboxを消去して既存の入力喪失保護へ移行する。他Nodeの切断では選択映像を消さない。時計同期が初めて成立したとき、または3秒の同期失効後に復帰したときは、古いバッファを破棄してキーフレームを再要求する。GPU上の表示切替時間・実デコーダ資源の回収は実機検証待ち。

ヘッダーの書き出しアイコンで診断JSONを保存する。schema 16の`nodeMonitoring`にNode ID、名前、接続・選択状態、計測値、取得時刻付き端末状態と`mediaControl`を保存する。値がない項目は省略し、0と区別する。以前の診断JSONではこのフィールドを省略できる。イベント用JSONLは状態スナップショットの連続保存ではない。

## 映像・深度の送信制御

各Nodeの一時停止／再開アイコンで、iPhoneからの映像と深度の送信を止める。Pose・時計同期・端末診断は継続する。取得とエンコードは止めないため、ARの追跡基準を維持できる一方、GPU・CPU・電力・温度の改善は保証しない。再開してもiPhone側で停止済みの撮影を勝手に開始しない。

`suspendMedia`／`resumeMedia`を認証済みTCPで送り、操作IDと要求状態が一致する`mediaControlResult`で確定する。応答待ちはNodeごとに1件、3秒でタイムアウトとし、状態を「不明」にする。古い操作・別接続・期限後の応答を適用しない。状態不明時の再操作は一時停止要求となり、確定後に再開できる。接続が変わると未処理操作を破棄し、新接続は送信可能状態から始まる。

停止応答後にMacのmailboxを非表示にし、再開時もキャッシュを空にしてキーフレームを要求する。デコード完了には送信制御の世代IDも照合し、停止前の遅延コールバックを再開後に表示しない。選択Nodeの送信停止は既存の入力喪失保護へ移行する。

TCPへ既に投入された映像・深度は取り消さないため、滞留時には操作応答も遅れる。受付枠は一時停止で解放しない。自動帯域判定、低優先度Nodeの自動停止、解像度・fpsの縮小はNext。

⭕️ [Pending] 実iPhoneでの送信量減少、停止中のPose・診断の継続、TCP滞留時の応答時間、HEVCキーフレーム復帰、深度再開、選択NodeのGPU出力保護を確認する。

## 接続の受付制限

標準の受付枠はNode 4台、映像能力を持つ接続4本。これは同時ストリームの固定予約で、GPU性能やWi-Fiの実測による帯域保証ではない。映像能力がないNodeは映像枠を使わない。未登録TCP接続は最大16本で、10秒以内に有効なHelloがない接続を切断する。

上限超過はNode登録とUDPセッション通知の前に拒否し、既存Nodeの枠を変更しない。切断で枠を解放する。同一Node IDの新しい接続は枠を置き換え、古い接続の切断で新しい予約を消さない。同じ接続の重複Helloは無視し、Node IDや能力の変更には再接続を必要とする。映像能力を宣言していない接続から映像を受けた場合は切断する。

Macのモニターには受付上限と拒否理由を表示し、診断JSONの`admissionLimits`と`admissionEvents`へ保存する。拒否履歴は直近32件、名前は128文字まで保持し、Hostを再起動すると履歴を消去する。iPhone側では現在は切断として見えるため、Macの拒否理由を確認して空きを確保した後に手動で再接続する。

自動テストは状態の失効、逆順・重複、同期喪失、不正値、未来時刻、Node間独立性、再接続後のシーケンスリセット、暗号化UDPの1200バイト上限と往復、診断スナップショットの往復を検証する。

## Universal Film Camera接続口

CameraのiOSネイティブ層からSwift Packageの `VPXIPhoneCapture` と `VPXCaptureProtocol` を利用する。MainActorで `CaptureNodeSessionModel(externalCapabilities: ...)` を生成し、実際に送れる `pose`・`depth` などだけを宣言する。外部モードではVPX側が撮影セッションを起動しない。Camera側がカメラ、センサー、エンコーダを所有する。

既存の発見・ペアリング・ホスト選択を使い、テレメトリ準備後に `startCapture()` を呼ぶ。生成された `externalCaptureID` をネイティブ側の送信処理に渡す。`submitExternalVideo` にはホストとの時計同期に使う端末単調時計で時刻を付けた、長さ付きNALのHEVCを渡す。キーフレームにはパラメータセットを付ける。`onExternalKeyFrameRequested` は送信開始、ホストからの要求、送信再開で呼ばれる。

同じIDで `submitExternalPose`・`submitExternalDepth`・`submitExternalQuality` を利用できる。停止・切断後の旧IDは無視する。UIへの公開は接続状態と操作に限定し、映像・センサーの送信処理はネイティブ側で接続する。Universal Film Camera iOSでは撮影設定の「VPX Studioに接続」から利用する。実機間の試験項目はROADMAPを参照。


Cameraが未圧縮のCVPixelBufferを渡す場合は、送信開始後に `makeExternalVideoInput(profile:)` を呼ぶ。返された入力口に撮影コールバックから `submit(_:hostTimeNanoseconds:metadata:)` で読み取り専用のバッファを渡す。端末の単調時計に変換した取得時刻を指定する。処理枠が埋まった場合や停止後は `false` を返す。入力口は停止・切断で無効化されるため、再接続時に作り直す。自前で圧縮したストリームを渡す場合は、同じ収録中に両方式を混在させず `submitExternalVideo` を使用する。

AVCaptureからは `submit(_:synchronizationClock:cameraID:metadata:)` に撮影サンプルとセッションの `synchronizationClock` を渡せる。APIは取得時刻をホスト時計に変換し、明示メタデータがない場合はバッファの色域・伝達特性・YCbCr行列の添付情報を使う。戻り値はキューへの受付結果。


CameraとVPX Studioは同じLANに接続する。MacのVPX Studioでペアリングを開始し、Cameraの撮影設定から「VPX Studioに接続」を開く。ホストを発見し、MacのQRを読み取り、確認コードを照合して接続する。送信開始後はシートを閉じて撮影画面に戻るとCameraのプレビューが再開し、その撮影サンプルがVPXへ送られる。送信を止める場合は接続画面を開き、停止を選ぶ。Cameraのバックグラウンド移行でも送信を終了する。

CameraのiOSビルドはiOS 18以上を対象とする。開発時はXcodeプロジェクトのローカルパッケージ参照先にVPX-Studioを置く。同梱した送信機能は映像を提供し、CameraからのPose・深度の送信実装はNext。
