# チェッカーボード対応点からの姿勢校正

既知の内部パラメータと、順序付きの内側交点からカメラのステージ姿勢を計算する。画像から交点を検出する機能ではなく、外部の検出器や測定工程が生成したJSONを取り込む校正ワークフロー。

## 操作

1. 対象の入力を選択し、その画像寸法・レンズ構成に対応する内部校正JSONを読み込む。必要なら校正読込ボタン横のコピーアイコンでcameraIDを取得する。
2. 未補正の元画像でチェッカーボード内側交点を測定し、下記形式で記録する。縮小画像や歪み補正済み画像の座標を、元画像の内部パラメータと混用しない。
3. Inspectorの「ボード対応点で校正」からJSONを選択する。カメラ／レンズ識別子・寸法・日時・数値・点配置を検査し、バックグラウンドで姿勢を計算する。
4. 成功すると校正プロファイルの新revisionへ反映し、RMSE・最大残差・測定日時を表示する。失敗時は既存の校正を保持する。入力・内部校正の変更や画面終了では処理をキャンセルし、古い結果を後から適用しない。
5. 保存アイコンからプロファイルを書き出す。追跡Nodeでは、カメラを計算された測定時の物理姿勢へ合わせ直し、「ステージを固定」で現在のNodeワールドへ結び付ける。過去画像の測定結果を現在のPoseへ自動で結び付けない。

本番中の校正変更は行わない。計算中はステージ固定とプロファイル保存を抑止する。入力がない状態では実機なしのファイル検証ができても、LIVE前の入力寸法・追跡・ステージ対応の検査を通ったことにはならない。

## 入力JSON v1

| キー | 内容 |
| --- | --- |
| schemaVersion | 1 |
| cameraID | 選択した入力のUUID |
| lensID | 対象レンズ構成。既存プロファイルがある場合はそのlensIDと一致させる |
| imageWidth / imageHeight | 元画像の整数画素寸法。内部校正と一致させる |
| columns / rows | 内側交点の列数・行数。それぞれ3〜20 |
| squareSizeMeters | 隣り合う交点間の実測距離、0.001〜1m。最大の交点間距離は10m以内 |
| imagePoints | `{ "x": ..., "y": ... }`の配列。列数×行数、最大400点 |
| stageFromBoard | 列優先16要素の剛体変換。ボード座標からステージ座標への対応 |
| measuredAt / expiresAt | Host側で記録した測定日時と有効期限、ISO 8601 |
| focusDistanceMeters | 任意の正のフォーカス距離。内部校正にbreathing表がある場合は必須で、表の範囲内に限る |

交点はボード座標で行優先とし、最初の行が+Y側、各行を−Xから+Xへ並べる。原点は内側交点群の中心、Z=0の平面、+Zはボード面の法線。画像座標は左上原点、+X右、+Y下。画像内で見える上から順に並べ直すのではなく、既知のボード上の点番号を維持する。

1MiB以下のファイル、有限値、画像内の点、有効な日時、剛体のボード姿勢を要求する。画像上で縦横とも20px以上の広がりが必要で、重複点や共線に近い配置を拒否する。未知のschemaVersionや不正な入力では既存プロファイルを変更しない。

## 計算と判定

Brown型の放射歪みk1／k2／k3と接線歪みp1／p2を反転し、正規化した平面対応からホモグラフィを求める。剛体姿勢を初期化した後、歪みを含む画像画素への再投影誤差を、減衰付きGauss–Newtonと縮小ステップで最大30反復調整する。保存するFloat変換へ丸めた後にも残差を再計算する。

平面点からの初期姿勢と再投影最小化の参考は、OpenCVの[平面ホモグラフィによる姿勢推定](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)と[PnPの座標・誤差モデル](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。実装はSwift／SIMDで、OpenCVを実行時依存に追加していない。

全点がカメラ前方にあることを要求し、光学カメラの+Y下／+Z前方をVPXの+Y上／−Z前方へ変換する。既知のstageFromBoardからworldFromCameraを計算する。内部パラメータ自体をこの単一画像から推定する機能ではない。

RMSEは`√(Σ(Δu² + Δv²) / 交点数)`、最大残差は交点ごとのユークリッド距離の最大値。RMSEが2px、最大残差が5pxを超える場合は採用しない。外れ値を自動除去して成功扱いにはせず、対応点を修正して再測定する。

breathing表がある場合は、宣言されたフォーカス位置の焦点距離に応じてfx／fyを評価して計算する。保存する基準fx／fy・基準焦点距離・breathing表は書き換えず、測定フォーカスを記録する。読込後の描画設定もその位置へ合わせる。

## プロファイル・本番前チェック

既存プロファイルのIDを維持してrevisionを増やす。旧形式から初めて生成する場合は新IDを発行する。測定方法、交点数・格子寸法、ボード姿勢、元の対応点、測定フォーカス、最大残差、反復回数をcheckerboardMeasurementへ保存する。診断JSON v13にもプロファイルを含める。

検証日時には入力のmeasuredAtを使い、有効期限は観測データと既存の内部校正の早い方にする。外部姿勢を測り直すだけでは内部校正の期限を延長しない。未来日時・期限切れの内部校正は再利用しない。

内部パラメータのsourceは維持する。推定値を使って低い残差が得られても、実測値やメーカー値へ昇格させず、本番前の推定値拒否は残す。既存ステージ対応は新しい外部姿勢に自動流用しない。

本番前チェックは、UIに設定された公称焦点距離と基準値の一致、breathing表がある場合のフォーカス範囲も検査する。公称焦点距離の許容差はmax(0.01mm, 基準値の0.1%)。フォーカスは表の両端を含む範囲内に限る。これは設定値と校正表の照合であり、実カメラのAF・ズーム位置の自動取得ではない。実機メタデータとの照合はNext。

## サンプルと検証

[Intrinsics.json](../Examples/Phase3/Intrinsics.json)と[CheckerboardObservation.json](../Examples/Phase3/CheckerboardObservation.json)は、6×5の内側交点、0.1m間隔、正面3mのカメラを表す合成データ。cameraIDはゼロUUID、日時は固定の例、内部パラメータはestimatedとしている。実機の校正値ではなく、識別子や日時を書き換えても実測値にはならない。

全125件のテストを通過。歪み付き既知姿勢、ボードのステージ変換、サブピクセル雑音、異常点・順序・退化配置、画像寸法・日時・剛体検証、フォーカス、誤カメラ・期限切れ、非同期キャンセル、revision更新、保存・再読込、失敗時の既存校正維持を確認した。日本語・英語のネイティブ画面で読込と操作状態も確認した。简体中文を含む3言語を実装している。

実ボードの印刷寸法、ボード姿勢・点番号の向き、複数距離・傾き・動きぼけ、レンズ実測値に対する外部姿勢の精度はPending。残差は入力点への適合度であり、独立した物理精度の認定ではない。平面姿勢の曖昧さや左右・180度の取り違えは、実際のボードの点番号と姿勢で検証する必要がある。

画像からの自動交点検出、複数画像による内部パラメータ校正、AprilTag検出、共分散推定、レンズエンコーダとの自動照合は引き続きNext。
