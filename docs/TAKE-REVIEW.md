# Take整合性チェック

ヘッダーの盾アイコンから整合性チェックを開き、フォルダアイコンで`manifest.json`を含むTakeフォルダを選ぶ。各アセットの種類、相対パス、SHA-256照合結果を表示する。再照合アイコンで現在のファイルを読み直す。

| 表示 | 意味 |
| --- | --- |
| 照合済み | manifestのSHA-256と読込内容が一致 |
| 未検証 | アセットは読めるが、旧manifestなどでSHA-256が未設定 |
| 欠落 | 参照先ファイルが存在しない |
| 変更あり | 保存済みSHA-256と不一致 |
| 読込不能 | 権限・形式・安全なパスの検証などで読込不可 |

全体を照合済みとするのは、1件以上のアセットがあり、全件が照合済みの場合だけ。空Takeは未検証とする。未対応manifest版、不正パス、重複パスなどは照合前に拒否する。manifest v1／v2に対応し、照合ではファイルを書き換えたり、ハッシュを自動的に付け直したりしない。

ハッシュ計算はUI・描画処理と別のactorで行う。各ファイルを1MiBずつ読み込み、中断を確認する。停止ボタン、別フォルダの選択、画面を閉じる操作で中断する。中断済み・置換前の結果を画面に反映せず、中断を「読込不能」と誤表示しない。選択フォルダのsecurity-scoped accessは照合処理の間だけ保持する。

結果はその照合時点のスナップショットで、照合後のファイル変更を監視するものではない。収録・書込みを完了したTakeに対して実行する。ハッシュ一致は再生可能性、映像品質、校正の適合性を保証しない。現在のReview画面は整合性チェック・設定保存・既存映像の再生に対応する。再合成や独立した音声・補助パスとの同期はROADMAPの未完了項目。

## 保存済み映像の再生

アセット表でcameraまたはcompositeの照合済み行を選び、再生アイコンを押す。再生前にmanifest全体がレビュー時点から変わっていないことと、対象映像のSHA-256を再照合する。未封印の旧Take、変更・欠落した映像、対象外の役割、Takeの外へ解決されるパスは再生しない。他アセットの欠落は、選択した映像の照合が成功する場合、その映像の確認を妨げない。

照合とAVFoundationのメディア読込みは非同期で行い、準備中は中断できる。再生開始後はAVKit標準の再生・一時停止・シーク操作を使用する。別映像の再生、別Takeを開く操作、再照合、画面終了時は現在の再生を停止し、プレイヤーitemとsecurity-scoped accessを解放する。中断前の準備結果を後から表示しない。OSが再生できない動画形式や再生中の失敗は、ローカライズしたエラーと詳細のツールチップで示す。

ハッシュ照合は再生開始前の確認であり、再生中のファイル変更を継続監視しない。書込み中のTakeを再生せず、変更後は再照合する。映像に含まれる音声は標準プレイヤーの対象となるが、独立したaudio／Pose／深度との同期や当時の設定での再合成は未実装。設定スナップショットには映像がないため再生対象はない。

元画像を使わない16×16・2フレームの合成H.264 fixtureで、AVFoundationの読込み・プレイヤー作成・停止後のitem解放を確認する。FFmpegはfixture再生成時だけ必要で、アプリやテストの実行依存には追加しない。

⭕️ [Pending] GUIでのシーク・音声・終了動作とレイアウト、実収録4K60／HEVC 10-bit／ProRes・外部ストレージの再生を確認する。

## 設定スナップショットの保存

保存アイコンで親フォルダを選ぶと、`VPX-Snapshot-<UUID>`という新しいTakeを作成する。映像・音声は収録しない。現在のプロジェクト設定、レンダリング設定・入力色変換・品質設定・同期状態・Node監視・送信制御を含む診断JSONと、読込済み校正があれば校正JSONを保存する。シーン名などの参照情報は診断に含まれるが、glTF／USD本体・テクスチャ・LUT・プラグインは同梱しない。

manifest v2の`provenance`は保存種別`configurationSnapshot`、作成ソフトウェア、機器一覧、校正参照を持つ。アプリの版情報がない開発ビルドは`development`／`local-build`と記録し、リリース番号を推測しない。機器の能力・役割・接続状態は現在のRegistryのスナップショットで、実機認定や役割制御の完成を意味しない。校正のID・revision・カメラIDは、同梱校正と診断JSONの内容が一致することを保存前に検証する。期限切れなどの運用品質は診断の校正状態を参照する。

同じ親フォルダの一時ディレクトリへ書き込み、全ファイルのSHA-256とmanifestを確定してから最終フォルダへ移動する。既存の保存先は上書きしない。公開前の失敗・キャンセルでは一時ファイルを片付け、未完成Takeを公開しない。最終移動開始後のキャンセルでは保存が完了する場合がある。保存後は自動で照合し、結果を表示する。

v1の読込みはID・設定・アセット・既存ハッシュを維持し、メモリ上の版だけをv2へ移行する。作成元ソフトウェアや機器情報は不明のまま残し、元のmanifestは変更しない。未知の将来版は拒否する。

自動テストで正常な保存済みTake、変更・欠落、旧ハッシュ未設定、空Take、キャンセル、未知のmanifest版、読取前後のmanifest不変を検証する。

⭕️ [Pending] フォルダ選択・長いパス・3言語・ライト／ダークのGUI表示と照合中断を確認する。今回の起動ツールがタイムアウトし、画面の実表示は未確認。実収録Take、外部ストレージ、大容量データの実運用速度も確認待ち。


## カメラ入力の収録

収録ボタンで親フォルダを選択し、停止で `VPX-Take-<UUID>` を確定する。現在の校正チェックに通った選択入力が対象で、出力はH.264 MOV。Metal合成、音声、独立した深度・Poseは含まない。フレーム時刻にはMac側の受信時刻を使用するため、複数ストリームの同期用収録ではない。

収録キューは最大4フレーム。処理が追いつかない場合は新規フレームを落とし、収録中のドロップ件数を `recording.json` に記録する。この値はカメラやネットワークの上流で失われたフレーム数を含まない。診断・校正は開始時点の状態を保存する。

MOVの書込み完了後、同梱ファイルをハッシュ化し、manifest v2を確定してから同じ親フォルダ内で完成Takeへ移動する。空収録や書込み失敗では完成Takeを公開しない。保存後はステータスバーの「Take保存済み」からReviewで照合・再生できる。

## 合成映像と音声の収録

収録メニューの「合成映像とマイクを収録」で保存先を選び、macOSのマイク許可後に収録を開始する。Metalビューポートの最終出力とMacの既定の音声入力を、`composite.mov` のH.264映像・48 kHzモノラルAAC音声として保存する。両トラックはMacのホスト時計を基準とする。音声の先頭は最初の映像フレームに合わせ、開始前の音声バッファを除く。

停止するとMOVを閉じてから、診断・校正・フレーム数と音声バッファ数を含む収録統計とともにハッシュを記録する。映像または音声が空の場合や書込みに失敗した場合は、完成Takeを公開しない。保存済みTakeはReviewの合成映像行から音声付きで再生できる。

出力寸法はビューポートに依存する。収録中にウィンドウのサイズ変更などで出力寸法が変わると収録は失敗するため、サイズは開始前に調整する。音量・機器間の遅延補正や長時間同期精度は実機での確認が必要。4K60の性能、権限ダイアログ、実マイクや外部ディスクを使用した検証はPending。


## マット・深度・Poseの同期データ

「合成映像とマイクを収録」で補助データも保存する。`frames.jsonl` はMOVに書き込んだ映像サンプルごとの索引で、0始まりの `frameIndex` と `ptsValue / ptsTimescale` 秒で対応付ける。元映像のシーケンスとホスト時計上の取得時刻も、利用できる場合に記録する。待ち行列超過などで落とした映像の索引行は作成しない。

- `matte.f16le` は合成パスのアルファを上の行から順に並べたfloat16 little-endianデータ。索引に幅、高さ、オフセット、長さを記録する。奇数寸法の右端・下端はMOVと同様に切り詰める。
- `depth.bin` はLiDARのfloat32 little-endian深度（m）とuint8 confidence。索引には各データの範囲、解像度、深度の取得時刻とシーケンスを格納する。深度はセンサー座標系のまま保持する。同じ深度を連続フレームが参照するときは範囲を再利用する。
- `pose` は索引行内の列優先4×4行列で、映像の撮影時刻に対して描画処理が解決したカメラ姿勢を記録する。実測、補間、予測の区別と予測時間も保持する。

対応データがない項目は省略する。深度は同じ入力の最新データが有効で、映像取得時刻との差が100ms以内の場合に採用する。ファイルが生成された補助データだけをmanifestに登録し、SHA-256で照合する。補助データの書き込みに失敗した場合はTakeを確定しない。Reviewでは整合性を確認できる。補助データの可視化と再合成は今後対応する。


## 10-bit入力の収録

収録メニューの「10-bit入力を収録（HEVC）」を選ぶ。入力には10-bit 4:2:0のビデオレンジまたはフルレンジのピクセルバッファが必要。Macカメラでは現在のネイティブ形式と出力が対応する場合に10-bitのまま取得する。エンコードはHEVC Main10を使用する。停止時にMOVの形式記述で輝度・色差の両方が10-bitと確認できた場合に、`recording.json` に `encodedBitDepth: 10` を記録してTakeを確定する。8-bit入力や検証に失敗したMOVでは完成Takeを公開しない。

このモードの収録対象はカメラ入力。合成出力用の設定は次節を参照。4K60の性能、実機の入力形式と色再現、HDRメタデータの保持はPending。


## 10-bit合成収録

「10-bit合成映像とマイクを収録」を選ぶ。Metalの同じ合成パスを16-bit浮動小数点ターゲットにも描画し、GPUで10-bit Rec.709 SDRの4:2:0ビデオレンジへ変換する。合成MOVはHEVC Main10映像とAAC音声を含む。マット・深度・Poseの索引とハッシュ付きTakeは従来の合成収録と同じ。停止時は完成MOVの輝度・色差の両方を確認し、10-bitと検証できた場合に公開する。HDRの合成出力と実環境での4K60持続性能は検証対象外で、実機確認はROADMAPのPendingを参照。


収録先のファイルシステムに256 MiB以上の空き容量が必要。収録中の書込み処理で空き容量を最大毎秒1回確認し、下回った場合はサンプル受付を停止し、それまでの映像からTakeの確定を試みる。容量取得に対応しない保存先では書込みエラーによる既存の保護が働く。収録中は処理待ちやエンコーダの都合で落とした映像フレーム数を表示する。
